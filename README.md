# daily-blog · 论坛式每日连载

一个仓库跑完整闭环：**挖题 → 取材 → 写作 → 建站 → 推送通知**。

站点是一个长帖，按页连载。每页由「1 楼主贴 + 若干楼层」组成，读起来像在翻一个不断更新的论坛帖，而不是一堆博客文章。

零依赖，`docs/` 就是站点。

## 每天怎么跑

```
每天 07:00 / 11:00 / 15:00 / 19:00 各触发一次（UTC 23,3,7,11）
  ├─ 挖题  扫 docs/posts/*.md，捞带「怎么/为什么/能不能/？」的句子，随机挑一条
  ├─ 取材  抓信源最近 48h 内容 → 从选题抽检索词 → 只挑命中的（最多 6 条）
  ├─ 写作  模型带着素材，写主楼长文 + 3~5 个楼层
  ├─ 落盘  写成 docs/posts/00N.md（页码自动递增）
  └─ 建站  重新生成整站，提交回 main
```

**为什么要设四个时间点**：GitHub 的定时任务会被延迟，甚至整点直接吞掉，这是它自己的机制，改不了。所以一天试四次，脚本自带幂等——当天已经写过就直接跳过，前面几次被吞了后面还能补上。

## 站点结构

```
docs/
  index.md          帖子开头的说明，显示在首页顶部
  posts/
    001.md          第 1 页
    002.md          第 2 页
    ...
```

- **首页 `index.html`** 就是第 1 页（不另外生成 `posts/001.html`）
- 其余页是 `posts/002.html`、`posts/003.html`
- 每页底部：`共 N 页 · 第 X 页` + 首页/上一页/页码/下一页/末页
- 另外还有 `search.html`、`feed.xml`、`sitemap.xml`

## 一页 md 怎么写

```markdown
---
title: 页面标题
date: 2026-11-20
---

# 页面标题

主楼正文，可以是几段 markdown。

## 2楼 · 网友·阿强 · 10:12
楼层内容。

## 3楼 · 网友·小北 · 10:20
可以反驳、可以追问。

## 4楼 · 楼主 · 10:35
楼主回复。
```

规则很简单：

- 第一个 `#` 是页面标题
- `#` 之后、第一个 `## N楼` 之前的内容是主楼（1 楼）
- 每个 `## N楼 · 作者 · 时间` 是一层，作者和时间都可省略
- 作者名里可以带 `·`（比如「网友·阿强」），解析时会按「最后一段像不像时间」来判断

文件名按数字排：`001.md`、`002.md`…… 你手动加一页就是 `005.md`，push 上去自动重建。

```

config/editorial.md             编辑偏好：写什么、不写什么

```

## 上线五步

1. **建仓库**，把本目录所有文件传上去（注意：仓库根目录下要直接看到 `.github`、`config`、`docs`、`scripts`，不能多套一层文件夹）。
2. **拿 Key**：openrouter.ai → Keys。
3. **加 Secret**：`OPENROUTER_API_KEY`（可选再加 `WECOM_WEBHOOK`，企业微信群机器人的地址）。
4. **开 Pages**：Settings → Pages → Source 选 `Deploy from a branch` → `main` + `/docs`。
5. **先自检**：Actions → `daily-post` → Run workflow → mode 选 **probe**，确认信源都通。

## 手动模式

- **auto** — 正常写一页
- **probe** — 只测信源
- **rebuild** — 不调模型，只按现有 md 重建整站（改样式后用）

命令行还能：

```bash
python3 scripts/generate.py -k 某个主题     # 指定主题，跳过挖题
python3 scripts/generate.py --force         # 今天写过也再写一页
python3 scripts/mine.py docs/posts          # 看看现在能挖出哪些疑问
```

`config/sources.json` 里：

```jsonc
"search": {
  "provider": "none",         // none = 只用信源素材
  "searxng_url": "",          // 改成 "searxng" 后填实例地址
```

## 一页的结构（连载怎么接上）

没有「楼主」这个概念，所有人都是楼层，页面上也不显示「第几楼」，只显示昵称和签名。

```
1 楼        只抛出问题 / 痛点 / 话题（来自上一页的候选），不展开
2 楼起      围绕它讨论、问答、辩论，每层 40~100 字
最后 2~3 层 各自抛出一个新问题，作为下一页的候选
```

md 里长这样：

```markdown
## @阿强 · 10:12
流量卡怎么办理才划算？同事那张 19 块 100G 的，用到第三个月就被限速了。

## @小北 · 10:20
只在运营商 App 里办，第三方代理便宜十块但没售后。
```

楼层标记是 `## @昵称 · 时间`。昵称和签名来自 `config/names.json`：

```json
[
  { "nick": "阿强", "sign": "十年运维，见坑就填" },
  { "nick": "小北", "sign": "在读研究生，穷但快乐" }
]
```

生成时这份名单会整个塞进 prompt，模型只能从里面选人，不能自己编名字。页面上每层只显示**昵称 + 签名**，不显示楼层号，也不显示时间（时间在 md 里保留着，需要时改 `floor_html` 加回来）。

旧格式 `## 2楼 · 阿强 · 10:12` 也认，只是页面上照样不显示楼层号。

**正文里不会出现一级标题**。页面顶部那个大标题是模板渲染的页面标题（取自 md 的 `#` 行），正文里的任何 `#` 都会被降级成 `##`，所以不会出现「标题在正文里再来一遍」。

**下一页的话题从哪来**：不再靠结尾留问题，而是直接从**已写过的评论**里挑。front matter 记本篇话题和头部信息：

```yaml
question: 老卡月租高，想换张流量卡，结果页面一堆套餐，越看越晕
author: 阿强                # 主笔 nick；无主笔时为空
tags: ["限速", "异地补卡"]   # 主题标签，显示在正文上方
```

挖题脚本（`scripts/mine.py`）扫历史 md 里所有 `## @昵称 · 时间` 的署名段落，按"具体性"打分后挑一条：

- **无主笔**（论坛 peers）：从讨论楼层里挑——那些给做法、反驳、追问的真实发言
- **有主笔**（lead_support）：从文末短评里挑——主笔长文不署名，不会被误选
- **导航/资源**（item_list）：从文末短评里挑；主题契约要求每页必写 2~3 条短评，保证这类站点也有稳定话题源

短评普遍偏短，所以后两种会用 `compact` 打分（10 字起、14 字即可拿长度分），10 字以内的泛评仍会被过滤。

命中的那句话原样成为下一篇的话题，1 楼把它摆出来讨论。话题来源排除最近 6 页，避免连着重复。结尾由主题结构要求自然收束（给结论、边界、争议点），**不写续问钩子**——这样话题是从真实讨论里长出来的，不是模型硬编的"下一期问题"。

**作者和标签**：作者取脚本按 seed 幂等分配的主笔（模型改不了），标签取模型在唯一一次请求里的产出、缺时用冻结关键词兜底。两者只作为内容写进 front matter，**显示位置由主题 `slots.header` 的 `byline` / `tags` 开关决定**——换主题不改脚本。

兜底：历史评论为空 → 用信源热点当话题；`-k` 可手动指定跳过挖题。

### 调用次数

正常情况下**一天只调 1 次模型**：

| 环节 | 谁来做 |
|---|---|
| 挖题 | 脚本扫历史评论打分挑选，不调模型 |
| 抽检索词 | 脚本规则（关键词池命中 + 英文整体 + 中文 2-gram），不调模型 |
| 写作 | 模型，一次出主楼 + 楼层，结尾自然收束（无续问字段） |

脚本抽词命中不足 2 条素材时，不会追加模型请求——按省资源契约就地兜底。

`config/writing.json` 的抽词开关：

```json
{
  "query_terms": "auto"         // auto=脚本优先，不够再问模型；script=只脚本；model=只模型
}
```

**纯脚本模式**（`"query_terms": "script"`）完全不用调模型抽词，最省，但遇到「小众产品名 + 抽象问题」这种组合时，命中率不如模型。
**纯模型模式**（`"model"`）抽词更准，多一次调用。

## 素材是怎么挑的

不是「抓什么喂什么」，是按选题筛：

1. 抓所有信源最近 48 小时的内容
2. 把选题（比如「流量卡怎么办理才划算？」）交给模型，抽 3~5 个检索词（`流量卡 / 办理 / 运营商`）
3. 用这些词去匹配标题和摘要，命中越多排越前
4. **只把命中的最多 6 条喂给模型**，一条都不命中就明说

日志里能看到筛选过程：

```
[daily] 检索词：流量卡、办理、运营商 ｜ 命中 2 条相关素材（信源共 3 条）
[daily]    · [流量卡,运营商] 运营商上线 19 元 100G 套餐，代理商渠道收紧
[daily]    · [流量卡,办理] 流量卡办理要实名，异地补卡麻烦
```

被过滤掉的比如主机发售、徒步指南，不会混进 prompt。

**一条都没命中**时，prompt 里会写「信源里没有相关内容，可以基于已有知识回答，但不要编造具体数字、价格、时间」，而不是塞一堆无关素材让模型强行关联。

**这里的能力边界要清楚**：信源是 RSS/接口，只能拿到「最近发布的内容」，没有历史检索。选题如果超出现有信源的话题范围（比如问一个小众软件的具体用法），命中的条数会是 0。真要按任意问题去全网找资料，得等 SearXNG 部署好，`search.provider` 改成 `searxng` 之后，搜索结果的优先级会高于信源。

**关键词抽取失败**（模型挂了）时，退回 2-gram 字符切分，效果糙一些但不会断。

## 搜索入口

顶栏右上角有个放大镜图标，点进 `search.html`。内联 SVG，不依赖 emoji 字体，各家手机显示一致。

## 额外内容（广告 / 段子 / 补充）

`config/ads.json`，会以**完全普通的楼层**插进页面，不带任何标记——可以是推广，也可以是一句段子、一条补充。

```json
{
  "per_page": 2,
  "items": [
    { "nick": "老陈", "sign": "开过店，赔过钱", "text": "支持 markdown 和 [链接](https://example.com)" }
  ]
}
```

- `per_page` 控制每页插几条，0 或删掉文件就不插
- 插入位置按页码哈希算，**每次构建结果一样**，不会产生无意义的 diff
- 会优先选正文里没出现过的昵称，避免「同一个人连发两条」的穿帮
- 插进来的楼层和正常楼层功能完全一致：能点开生成图片、能点链接

## 看图模式

楼层右上角有个图片按钮，点它进入全屏浏览，**上下滑动切换楼层**：

- 手指上滑 = 下一条，下滑 = 上一条；桌面用滚轮或 ↑↓ 方向键
- 左上角 × 退出，右上角 ⤓ 下载当前这张
- 底部显示「3 / 12」，知道自己看到哪了
- 退出时页面**自动滚回**你最后看的那一层，不用重新找

配背景图：放进 `docs/assets/cards/`，在 `config/names.json` 里对应昵称加 `card` 字段：

```json
{ "nick": "阿强", "sign": "十年运维", "card": "aqiang.jpg" }
```

- 建议 1080×1440（3:4），文字从画面上方 18% 开始，中上部留白
- 文字白色带阴影，背景别选太浅的
- 没配 `card` 的昵称自动用深色渐变底，照样能出图
- 图片是浏览器本地合成的，不上传服务器
- 弹层用 `100dvh` + `safe-area`，iPhone 刘海屏和地址栏伸缩都不会截断

## 速度

**页面加载**：首页 HTML 约 3.7KB（gzip 后 1.5KB），CSS 8KB 外链缓存一次，字体用系统字体零请求。搜索索引单独放 `search.json`，进搜索页才拉取，不拖累其他页面。卡片脚本是 `assets/cards.js`，全站共用一份，浏览器缓存后翻页不重复下载。

实测（30 页 180 层）：首页从 7.4KB 降到 3.7KB，搜索页从 16KB 降到 4KB。

**生成耗时**：采集 6 个源串行实测 3.9 秒，不是瓶颈；时间几乎全花在模型调用上（1~3 次，每次十几秒到两分钟）。所以「快」的关键是少调、短输出，不是优化代码。

想再压：
- 背景图转成 WebP，1080×1440 的 JPG 通常能从 300KB 降到 80KB
- 卡片脚本加 `defer`（已加），不阻塞首屏
- HTML 不用手动压缩，GitHub Pages 自带 gzip，压完差别不到 10%

## 分享卡片

每个楼层右上角有个「卡片」按钮，点开会把这条发言合成到一张图片上，可以下载发朋友圈。

**配背景图**：把图片放进 `docs/assets/cards/`，然后在 `config/names.json` 里对应的昵称上加 `card` 字段：

```json
{ "nick": "阿强", "sign": "十年运维，见坑就填", "card": "aqiang.jpg" }
```

- 建议 **1080×1440**（3:4），文件名用英文，中文也行但要 URL 编码
- 文字从画面上方 18% 开始排，左边距 8%，**中上部留白**，别把背景主体放在文字区
- 文字是白色带阴影，背景选深色或中等明度的图，太浅会糊
- 没配 `card` 的昵称会自动用深色渐变底，照样能出图

**排版规则**：昵称 → 签名 → 正文。正文超过画面会自动缩字号（最多缩 5 次），还放不下就截断加省略号。预览窗里看到什么，下载的就是什么。

图片是浏览器本地合成的，不上传服务器，也不产生额外请求。

## 三个容易被忽略的配置

| 文件 | 用在哪 | 作用强度 |
|---|---|---|
| `persona.md` | 写作调用的 system prompt 开头 | 强——决定语气，改一句效果立竿见影 |
| `editorial.md` | 写作 prompt 的「不要写这些」段 | 中——只管边界，不管写得好不好 |
| `keywords.txt` | 素材打分 + 脚本抽词优先 | 弱——顺序被「按选题匹配」接管了，但仍参与排序和抽词 |

`keywords.txt` 的作用变化值得知道：早期它是选题的核心依据，现在主要变成两件事——给素材做次级排序（相关度相同时才比它），以及脚本抽检索词时优先匹配池里的词。所以它不再决定「写什么」，只影响「用哪条素材」。精不精已经没那么重要，但留着比空着好。

## 提示词都在配置文件里

写作规范不写在代码里，改文本就行，改完下一次运行生效，不用重新部署。

```
config/prompts/
  write.md      写作：结构、干货规则、格式要求（最长，主要改这个）
  terms.md      抽词：脚本命中不够时，让模型从选题里抽检索词
  question.md   补问题：楼层里没留下新问题时，补问一次
```

模板里用 `{{变量名}}` 占位，`write.md` 可用的变量：

| 变量 | 内容 |
|---|---|
| `{{today}}` | 今天的日期 |
| `{{seed}}` | 这一页要讨论的问题（含来源页） |
| `{{material}}` | 从信源挑出的相关素材 |
| `{{recent}}` | 最近写过的页面标题 |
| `{{mw}}` `{{page_max}}` | 1 楼字数 / 整页字数 |
| `{{fc_min}}` `{{fc_max}}` | 楼层数区间 |
| `{{fw_min}}` `{{fw_max}}` | 每层字数区间 |
| `{{names}}` | 出场名单（昵称 + 签名） |
| `{{extra}}` | `writing.json` 里的 `extra_rules` |

占位符用双花括号，所以模板里写 JSON 示例时单个 `{}` 不会被吃掉。

**换主题**：比如从"工具效率"换成"数码评测"，改三个地方就够——
`config/prompts/write.md` 的结构和语气、`config/keywords.txt` 的关键词、`config/names.json` 的出场人物。代码一行不用动。

想同时维护多套，把这三个文件复制成别的名字，换主题时替换回来。

**模板文件删了也不会崩**，代码里有内置的精简版兜底，只是写出来的质量会差一截。

## 篇幅和干货程度怎么调

都在 `config/writing.json`，改完下一次运行就生效：

```json
{
  "main_words": 600,
  "floor_count": [3, 5],
  "floor_words": [40, 120],
  "extra_rules": "如果某个点在网上随便一搜就有，就别写；读者是来找你这句话的，不是来找百科的。"
}
```

| 字段 | 作用 |
|---|---|
| `main_words` | 主楼目标字数，上限是它的 1.2 倍（600 → 最多 720） |
| `floor_count` | 楼层数量区间 |
| `floor_words` | 每层字数区间 |
| `extra_rules` | 追加的写作要求，直接拼进 prompt，写多严都行 |

也可以用仓库 Variable `WORD_COUNT` 临时覆盖主楼字数，优先级高于配置文件。

生成后还有一道校验：字数低于 `main_words × 0.5`（最少 300）直接判定失败，不会把半截东西发出去。

## 关于「干货」

prompt 里有一组硬规则，不是让它"写得干货一点"这种空话：

1. 每一段必须带一个具体信息——事实、数字、做法、或明确判断，做不到就删掉这段
2. 禁止铺垫句、转场句、总结句、空洞形容，并给了具体例子
3. 不许科普常识
4. 同一件事只说一遍
5. 宁可短，不要凑字数

这些规则写在代码里，`config/editorial.md` 负责"写什么不写什么"，`writing.json` 的 `extra_rules` 负责补刀。三个地方分工，别混着写。

## 一级标题

正文不带 `#`。模型被明确要求把标题单独放在 JSON 的 `title` 字段里，脚本再兜底剥掉正文开头的一级标题——双保险，不会出现标题在页面里显示两遍。

你手写 md 时仍然可以写 `# 标题`，`blogsite.py` 解析时会把它提取成页面标题，不当作正文。

## 模型：只用免费

默认纯免费，不用配。每次运行拉 OpenRouter 模型表，筛价格全为 0 的，按写作适配度排序挨个试，`openrouter/free` 兜底。

`FREE_ONLY` 默认 `1`，硬过滤——哪怕配置里填了付费模型也会被剔除。

某个免费模型报 403（比如「only available on agentic harnesses」）会**拉黑 7 天然后换下一个**，不是 Key 问题。真 Key 失效是 401，会立刻停下。

## 定时没跑怎么办

按顺序查：

1. **仓库根目录**是不是直接就是 `.github`、`docs` 这几个目录
2. Actions 左侧有没有 `daily-post` 这个 workflow
3. Settings → Actions → General，确认 Actions 没被禁用
4. 默认分支是 `main` 还是 `master`

另外 GitHub 的 schedule 本身不可靠，延迟一小时很正常，偶尔整天跳过。这就是为什么要设四个时间点。
